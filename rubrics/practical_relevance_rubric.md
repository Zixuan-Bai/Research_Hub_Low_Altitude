# Practical Relevance Rubric

Use this rubric before generating or approving route cards.

## 1. Real System Connection

5: Related to deployed or clearly planned systems.

3: Plausible system connection, but evidence is incomplete.

1: Mostly academic framing with no clear deployment path.

## 2. Policy or Standard Relevance

5: Directly tied to standards, regulation, or policy needs.

3: Related to policy or standards but not central.

1: No clear policy or standard connection.

## 3. Parameter Usefulness

5: Provides concrete parameters such as latency, reliability, density, frequency, bandwidth, coverage, or safety thresholds.

3: Provides qualitative constraints.

1: Provides little practical parameter information.

## 4. Deployment Plausibility

5: Assumptions match plausible near-term deployment.

3: Some assumptions need verification.

1: Assumptions appear unrealistic or speculative.

## Decision

- `practically grounded`: strong route-card support.
- `needs practical validation`: keep surveying before route generation.
- `deployment uncertain`: do not create implementation repository.
